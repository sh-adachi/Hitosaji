# ひとさじ — Hitosaji

食事と栄養の記録を、毎日続けやすくする日本語の iPhone アプリです。SwiftUI と Swift Charts で実装し、iOS 17 以降に対応しています。

カロミルの「食品を選び、食べた量を調整する」流れと、あすけんの「食事を記録して栄養・体重の推移を確認する」考え方を参考に、独自の画面とデータで制作しています。

画面例（架空のサンプルデータ）：[きょう](Artifacts/today.png)・[食品](Artifacts/foods.png)・[ふりかえり](Artifacts/trends.png)・[食事入力](Artifacts/meal-editor.png)。

## 起動する

1. Xcode 26 以降で `Hitosaji.xcodeproj` を開きます。制作環境は Xcode 26.3、Swift 6.2.4 です。
2. Scheme を **Hitosaji**、実行先を iPhone シミュレータに選びます。
3. `⌘R` で起動します。初回の食事・体重・マイ食品は空の状態です。

実機では `Config/Signing.local.xcconfig.example` を `Config/Signing.local.xcconfig` にコピーし、`DEVELOPMENT_TEAM` を自身の Team ID に変更してください。必要に応じて Xcode の Signing & Capabilities で Bundle Identifier を変更します。ローカル署名設定は Git の対象外です。

食事の検索・手入力・集計は、外部パッケージ、API キー、サーバー、アカウント登録なしで使えます。写真の AI 解析には、別途解析サーバーと OpenAI API キーが必要です。

## できること

| 画面 | 内容 |
| --- | --- |
| きょう | 日付選択、朝食・昼食・夕食・間食への記録、編集・削除、摂取カロリーと PFC、食物繊維・食塩相当量の確認 |
| 食品 | 内蔵 20 品とマイ食品の検索、マイ食品の追加・編集・削除、食品から食事を記録 |
| ふりかえり | 7 日・30 日の摂取エネルギー、記録日の平均、体重の推移、体重の登録・編集・削除 |
| 写真から記録 | 写真選択・撮影、AI による複数料理の推定、料理の採用・除外と修正、一括保存 |
| 設定 | 栄養目標の変更、写真解析の接続設定、保存件数と使い方の確認、読み込み失敗時の再読み込み |

栄養成分表示を見ながら食品を手入力できます。よく食べるものはマイ食品に保存できます。同じ日の体重を再登録すると、その日の値を更新します。

バーコード検索、クラウド同期、HealthKit 連携、専門家の助言、運動記録は実装していません。写真解析を実行したときだけ、選んだ写真と補足を解析サーバー経由で OpenAI へ送信します。体重や食事履歴は送信しません。

## 写真の AI 解析

1. [解析サーバーの手順](Server/README.md)に従い、`OPENAI_API_KEY` と `HITOSAJI_ANALYSIS_TOKEN` をサーバー側に設定して起動します。OpenAI API の利用料金は別途発生します。
2. アプリの「設定 → 写真の AI 解析」でサーバーの **ベース URL**（パスなし）とアクセストークンを保存します。OpenAI の API キーをアプリに入力する必要はありません。
3. 食事の追加から「写真からAIで記録」を選び、写真ライブラリまたはカメラから写真を用意します。料理や量の補足も入力できます。
4. 「写真を送信して解析」を押します。結果の料理・基準量・栄養値を確認し、必要なら修正・除外して記録します。

写真は端末で長辺 1,600 px 以下の JPEG に変換し、位置情報などの元のメタデータを引き継ぎません。解析結果は最大 12 品で、写真に写った量の概算です。食物繊維・食塩相当量が不明なときは空欄を維持します。結果は自動保存せず、選択した料理を一度の保存処理で記録します。記録のメモには AI 推定であることと推定理由が残ります。

接続設定は端末の Keychain に保存し、写真はアプリの記録や付属サーバーのディスクに保存しません。OpenAI へのリクエストには `store: false` を指定しますが、これは OpenAI 側での一切の保持を保証する設定ではありません。[OpenAI のデータの取り扱い](https://developers.openai.com/api/docs/guides/your-data)も参照してください。

通常の接続先は HTTPS が必須です。Debug ビルドに限り、シミュレータから Mac 上の `http://localhost:8787` へ接続できます。実機・公開運用には HTTPS のサーバーが必要です。付属サーバーは単一利用者向けで、一般公開するサービスのユーザー認証・課金管理は含みません。

## 栄養値の扱い

- 内蔵 20 品は一般的な食品の**概算例**です。公式食品データベースやカロミル・あすけんの食品データを取り込んだものではありません。商品や調理方法で異なるため、記録時に実際の栄養成分表示へ修正できます。
- 栄養値は「茶碗 1 杯・150g」「100g」などの**基準量あたり**です。記録量は栄養値に倍率を掛けて計算します。半分なら `0.5`、2 個分なら `2` を入力します。元の基準量の値は保持します。
- カロリー・たんぱく質・脂質・炭水化物は必須です。食物繊維・食塩相当量は空欄にできます。空欄は不明として扱い、同じ日の記録に不明値があれば、その栄養素の日計も「未入力あり」とします。
- マイ食品を編集・削除しても、保存済みの食事の栄養値は変わりません。食事記録は登録時の値を保持します。
- グラフの平均は記録がある日だけを対象にします。未記録日を `0 kcal` として平均に含めません。
- 初期目標は画面用の**入力例**で、個人向けの推奨値ではありません。設定で変更できます。過去の日付も現在の目標と比較し、目標の変更履歴は保持しません。
- PFC のバーは目標に対する記録量です。構成比や健康状態の評価ではありません。

誤入力を防ぐため、基準量あたりの値は 0〜20,000 kcal、PFC・食物繊維は 0〜2,000g、食塩相当量は 0〜200g、倍率は 0 より大きく 100 以下、体重は 0 より大きく 500kg 以下に制限しています。目標値には正の数が必要です。これらは入力の上限であり、摂取推奨量ではありません。

食事・体重の記録日は日付（`yyyy-MM-dd`）として保存します。端末のタイムゾーンを変更しても、選んだ記録日は維持します。初期開発版の日時形式は、最初に読み込んだ端末のタイムゾーンで日付へ移行します。

## 保存とエラー時の動作

記録はアプリの `Application Support/Hitosaji/` に保存されます。

| ファイル | 用途 |
| --- | --- |
| `data.json` | 食事、体重、マイ食品、現在の目標。形式バージョンは `1` |
| `data.backup.json` | 保存直前の、読み取りと検証に成功したデータ 1 世代分 |

保存前に入力と既存ファイルを検証し、バックアップを作成した後、主ファイルをアトミックに書き込みます。バックアップ作成に失敗した場合も、主ファイルを更新しません。保存に失敗すると画面の保存済みデータも更新せず、エラーを表示します。

破損・未対応形式・不正値を含む既存ファイルを、自動的に空データへ置き換えることはありません。読み込み失敗後は保存を停止し、設定から再読み込みできます。バックアップの自動復元やアプリ内のインポート・エクスポートは未実装です。アプリを削除すると端末内のデータも失われます。

## 検証

Foundation のみで動作する `NutritionCore` を Swift Package として切り出しています。

```sh
./Scripts/test_core.sh
```

単体テスト **19 件の成功を確認済み**です。倍率と編集、日付境界・夏時間、不明な栄養値、入力検証、保存とバックアップ、破損ファイルの保護を確認しています。実行時のキャッシュと生成物は `.build/core/` に配置します。スクリプトの `--disable-sandbox` は SwiftPM の入れ子サンドボックスを無効にする指定です。

画面操作のテストは以下で実行できます。iPhone 17 Pro シミュレータが必要です。

```sh
./Scripts/test_ui.sh
```

iPhone 17 Pro（iOS 26.3）でビルド・起動と画面操作 6 シナリオの成功を確認しています（5 件は 10/3、1 件は 10/4 の単独再実行）。アプリのビルド・シミュレータ操作・UI テストの詳細は [検証記録](Artifacts/Verification.md) を参照してください。

```text
App/          SwiftUI の画面と状態管理
Core/         モデル、集計、入力検証、JSON 保存、写真解析の応答検証・通信
Server/       OpenAI 画像解析 API の中継サーバーとテスト
Tests/        Foundation の単体テスト
UITests/      アプリ操作のテスト
Config/       ローカル署名設定
Scripts/      検証スクリプト
Artifacts/    検証結果
```

UI テストの起動引数 `--uitesting` は保存先を `Hitosaji-UITests` に分けます。`--reset-data` はそのテスト用保存先のみを消去し、`--sample-data` はテスト用の架空データを用意します。通常起動でサンプルの食事が自動登録されることはありません。
